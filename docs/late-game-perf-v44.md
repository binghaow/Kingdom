# v44 后期性能（400–500 单位）

分支 `feature/late-game-perf`（基于 main 6560353）。问题：四国各约 100 人口的后期局面在 32 寸台式机上像幻灯片、操作延迟上升。分辨率上限（expansion.js render budget）已有，这次处理每单位的模拟和绘制开销。

## 测量方法

| 工具 | 场景 | 性质 |
|---|---|---|
| `scripts/perf/late-game.cjs` | Node，coast_l 四国（不同队伍），每国约 110 单位（含村民），AI 开；每国 2/3 士兵向地图中心推进交战；固定指令脚本（第 300 步 0 队攻击、600 步 1 队撤退、900 步 2 队进攻 3 队城镇）。 | 本机 Node 模拟，0.05 s 一步 |
| `scripts/perf/late-render.cjs` | 真实游戏，headless Chromium 1920×1080，四国 412 单位，四支约 70 人的军队在玩家城镇旁同屏交战，AI 开，`?perf=1` HUD。 | 无 GPU 的软件光栅 + 2 个共享核：只用于提交之间对比，不是真机帧率 |
| `scripts/release/late-cost.cjs` | 上面两者合并（Node 3 次中位数、浏览器 2 次中位数），已接入 `npm run release-check` 的「后期」一节。 | 同上 |
| `scripts/perf/late-determinism.cjs` | 导出某个提交的 `public/`，与工作区用同种子、同指令跑 1200 步（60 s），每 100 步比对状态指纹。 | 确定性检查 |

“改前”= main 6560353 用同一脚本测（`KINGDOM_ROOT` 指向导出的旧代码），“改后”= 本分支。同一台机器、同一天。

| 指标 | 改前 | 改后 |
|---|---|---|
| FPS（rAF 中位帧间隔） | 8.6 | 12 |
| 帧间隔 p50 / p95 | 116.7 / 191.7 ms | 83.4 / 125 ms |
| sim.tick p50 / p95 | 10.4 / 66.8 ms | 5.7 / 13.9 ms |

| HUD 遮挡轮廓 / 实体 / 单位 | 16.0 / 11.5 / 10.3 ms | 2.0 / 4.1 / 3.4 ms |

## 改动（按收益）

1. **`byId` 索引**（engine.js）：id→实体 Map，按 units→buildings→nodes 顺序取第一个（含 hp≤0 仍在数组里的实体），数组被替换（filter/赋值）或长度变化（push）时重建。结果与原三次 `find` 完全相同。
2. **自动索敌**：先做平方距离判断，再调用（无副作用的）`canTarget` 链；炮塔先过滤射程内单位再 `canTarget`，射程内最近的合法目标就是原来会打的那个。
3. **`blocked`**：每种建筑一个精确可达上界（墙半宽 ≤48、pad ≤18），先排除远处建筑；城墙检查只遍历缓存的墙列表（按建筑数组缓存）。
4. **迷雾**：一个格子本轮已对所有盟友可见时跳过距离和视线计算（写入本来就是空操作）。
5. **寻路网格重建**：拆成 `blockedTerrain` / `blockedBuildings`；建网格时地形用按世界缓存的陆地/海洋掩码（同一函数算出，世界签名变化即重建），建筑用 192 px 格索引。
6. **A\***：同一步内相同（网格、起点格、终点格或被挡终点坐标）的查询共用结果，调用方拿到新的路点对象。
7. **渲染**：血条高度和遮挡预判用按姿态缓存的轮廓（不再每个动画帧为每个受伤单位重画精灵 + `getImageData`），`entityBounds` 本身仍是逐帧精确的（预览检查依赖它）；屏上单位 >120 时遮挡幽灵轮廓按姿态缓存；视口外 360 px 以上的特效不画；采集碎屑用重置变换代替每片 save/restore；自动存档直接拼接 `serialize()` 的 JSON（同样的文本，少一次 parse + stringify）。
8. **attack-art 缓存**：桌面（精确指针）动作集预算 80→160 MB、队伍着色帧 28→72 MB，四国会战不再被逐出后重新解码/着色；触屏设备保持 V41 预算。

## 确定性

`node scripts/perf/late-determinism.cjs --ref 6560353`：5 个场景各 1200 步（60 s 模拟），每 100 步比较所有单位的 id/兵种/队伍/坐标/血量、建筑血量、资源点余量和各方资源（取 0.01 精度），**全部一致**：

| 场景 | 单位 | 结果 | 每步均值 改前→改后 | p95 改前→改后 |
|---|---|---|---|---|
| coast_l 种子 9090 | 397 | 一致 | 16.0 → 7.0 ms | 44.2 → 13.9 ms |
| coast_l 种子 31337 | 397 | 一致 | 14.6 → 6.9 ms | 41.4 → 15.6 ms |
| cliff_s 种子 4242 | 289 | 一致 | 8.9 → 4.1 ms | 36.0 → 10.1 ms |
| lake_s 种子 777 | 293 | 一致 | 9.7 → 4.4 ms | 25.3 → 9.2 ms |
| straits 种子 2024 | 325 | 一致 | 11.7 → 5.5 ms | 31.9 → 12.4 ms |

所有模拟改动都只读 sim 状态、不依赖时间或帧率；缓存都以数组身份/长度、`s.time` 或网格对象为键。渲染侧改动（轮廓缓存、特效裁剪、attack-art 预算）不进入模拟。

## 没有做的（原因）

- **AI 分帧**：AI 决策每 7 s 一次，四方合计约 17–26 ms；每步的 AI 层（dynasties / ai-humanlike / frontier-v40）各自 <2%。把各方 AI 摊到不同步会改变决策时刻和状态，违背逐位一致，所以只记录不改。
- **同步重寻路尖峰**：一起下令的单位每 1.8 s 同一步重算路径（约 200 次 A\*、约 45 ms）。错开会改变状态；本次只做了同一步内相同查询共享。
- **按负载降级细节**：试过大会战时草丛减半，headless 下没有可测收益（草丛 pass 的时间主要是地形图层的光栅刷新），已撤回；伤害数字（已按格合并）和战斗粒子（已有 600 上限与视口裁剪）保持原样。

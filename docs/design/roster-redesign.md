## 1. 设计目标与原则

兵种从约 50 个可训练单位减到每国约 20 个，建筑从 45 个减到约 21 个，让每一次建造和出兵都有明确理由，再把腾出的开发精力投入随机性和探索。

现在的问题不是内容少，而是选择少：大量兵种和建筑之间没有取舍关系，造或不造差别不大，造哪个也差别不大。

判断一个兵种或建筑该不该留，用四条标准：

1. **唯一职责**：它做的事，别的单位做不了或做得明显差。
2. **一眼可辨**：玩家看外形和名字就知道它克什么、怕什么。
3. **有代价**：选它就意味着放弃别的东西（资源、人口、时代、时间）。
4. **越晚越值**：高时代的单位或升级，在同样的资源或人口下要比早期更强，否则成长感是假的。

有序性：同类单位排成清楚的升级线，而不是并列的多个变体；一个建筑负责一类事情；每个时代解锁的东西要能回答“这个时代我获得了什么新能力”。

## 3. 精简后的兵种方案

每国约 20 个可训练单位：陆军战斗单位 9 个、攻城 2 个、支援 1 个、经济与海军 7 个、空军 2 个、英雄 1 名。同一条线上的兵改成“研究升级”，不再是三个独立兵种。

### 3.1 克制关系

- 长枪线克骑兵；骑兵克远程与攻城；远程线克长枪。
- 散兵专克远程线；掷弹兵专攻建筑。
- 克制倍率从 ×1.65 提高到约 ×2，并给每类兵一个护甲类型。具体数值用模拟对战校准（见第 9 节）。

## 4. 空军（方案 A）

只保留侦察热气球和双翼轰炸机，各自承担陆军和海军做不到的事，同时给地面加防空。

- **侦察热气球**：提前到 III 时代，降低价格，大范围视野，飞越地形；用来侦察敌人的打法和发现野外据点。
- **双翼轰炸机**：只攻击建筑，飞越城墙，弹药有限需回航补弹。
- **防空**：远程线和箭塔可以对空（伤害打折），要塞对空全伤害。
- 删除运输飞艇、武装运输飞艇、航空母舰、舰载双翼机。飞艇工场保留。

## 5. 兵种信息面板

目标：玩家选中一个兵，或在兵营点训练按钮上的 ⓘ，几秒内就能看懂三件事：它现在有多强、它克谁又怕谁、它还能升级到多强。

### 5.1 现状

底部选中面板已显示攻击、防御、射程；训练按钮的 ⓘ 详情弹窗（`public/campaign-ui.js`）已显示造价、训练时间，以及少数单位的专属克制加成。但它不显示通用克制关系（`public/empires.js` 的伤害倍率）、不显示“怕谁”，也不显示升级路线。在现有面板和弹窗上扩展，不新造一套界面。

### 5.2 底部选中面板（选中一个兵）

| 字段 | 说明 |
| --- | --- |
| 生命 | 当前 / 上限 |
| 攻击 | 每次伤害与每秒伤害，已含科技与老兵加成；加成部分用绿色小字标出，如「21（+3）」 |
| 护甲 | 数值和护甲类型（步兵甲、骑兵甲、建筑等） |
| 射程与速度 | 用“近 / 中 / 远”和“慢 / 中 / 快”小标签加数字 |
| 克制 | 一行两个图标组：「克 ⚔ 骑兵 ×2」「怕 ⚠ 远程 ×2」 |
| 升级 | 当前阶段，如「长枪线 1/3」 |

多选时显示每类兵的数量和总生命，点其中一类可切到该类的单体面板。选中敌方兵时同样显示，并把“怕”的那一类写成“用什么对付它”。

### 5.3 训练按钮的 ⓘ 详情

1. **一句话定位**：如「便宜耐打的反骑兵。怕远程。」，放在最上面。
2. **战斗力概览**：生命、每秒伤害、护甲、射程、速度、人口，以条形条对比同兵营其他兵。
3. **克制关系**：“克制”与“被克制”两列，各列出兵种图标与倍率。
4. **升级潜力**：这条升级线全部阶段，每阶的数值、所需时代与研究费用，当前阶段高亮；再列出铁匠铺里对它生效的科技，已研究的打勾。

### 5.4 实现要求

- **单一数据源**：把 `empires.js` 里的倍率规则抽成一个可调用的函数，伤害计算和界面都调用它，界面里不得手写倍率。
- **显示实际值**：所有数字含科技、国家和老兵加成，和战场上的结算一致。
- **不影响模拟**：纯界面，不写入模拟状态，不改变存档和联机协议。
- **中英文**：所有新文字走现有本地化文件。
- **界面审查**：按 AGENTS.md 的 frontier-ui-audit 流程，在手机竖屏、手机横屏、iPad 横屏和桌面，中英文、操作栏展开和收起各情况下检查。手机上克制一行放不下时，只显示图标与倍率。
- **顺序**：可以在兵种精简之前先做；升级线一栏等升级机制做好后再开启。

## 7. 腾出的精力投向哪里

### 7.1 电脑对手的打法

现在的电脑按固定间隔进攻（`public/dynasties.js`：标准难度每 200 秒 8 个兵，专家每 110 秒 16 个，目标永远是主城）。改成每局随机一种隐藏打法，玩家要侦察才知道：

- **快攻**：早期小规模骚扰，针对农民。
- **憋经济**：前期很安静，快速升时代，然后大军压境。
- **扩张**：抢占野外据点和资源区。
- **龟缩**：城墙和防御塔，轰炸和攻城。

通用能力：侦察玩家并针对玩家的兵种出克制；打不过就撤退；进攻时间和路线有随机性。

### 7.2 野外据点

地图上放置有守卫的据点，占领后持续给收益（黄金、视野、特殊兵种）。家里的资源设为有限，逼玩家中期出门扩张。现有的 KC 要塞、野兽、遗迹可以直接作为据点的基础。

### 7.3 地图随机性

每局的地形、森林、金矿和据点位置不同，但保证双方公平。用噪声生成河流、森林带和咽喉要道。要和联机的确定性改造协调：地图要么在所有设备上生成得完全一致，要么由房主生成后发送给其他人。

## 8. 美术复用与素材需求

完整审查、新素材规格与中英文提示词见 `docs/design/art-audit.md`。要点：

- 保留兵种都有四方向站立图和四方向各 4 帧攻击/工作动画，可以直接用；升级线不需要三套新图，现有图可当一、二、三阶。
- 最大缺口是行走动画：每个方向只有一张静态图。上线必需的新素材约 50 次生成加 8 次编辑、约 1,200 帧，最优先是四方向行走。
- 需要修或重做：近卫戟兵（现为剑盾）、长枪步兵攻击（长枪变短矛）、粮食磨坊与矿物收集场（无透明 JPEG）、飞艇工场白边、城墙城门、普鲁士掷弹卫队与村民采食的攻击图背景、鸢尾花徽记、红十字。
- 代码侧问题：`painted-architecture.js` 的 `ornament()` 在建筑上叠加矢量装饰，违反“不得出现漂浮色块”规则，改代码即可。
- 上架前授权风险：红十字标志必须替换；App Store 图标须完全不透明；`functional-buildings-v1.jpg` 缺生成记录；`docs/app-store-readiness.md` 的素材登记表需补全。

| 检查项 | 内容 | 判 FAIL 的条件（相对基线） |
| --- | --- | --- |
| 单位路径 | 开局、200 单位会战、围攻被围死目标、大编队一次下令；寻路次数、展开节点、耗时、失败率；卡住单位检测 | 寻路次数或展开节点增加 20%；卡住单位多于基线 |
| 模拟开销 | 50/100/200/400 单位每步耗时与分项 | 耗时增加 20%；增长指数变差 0.25 |
| 渲染 | 桌面与手机视口帧耗时、每帧绘图调用 | 绘图调用增加 35%；帧间隔变差 30% |
| 服务器与联机 | 每次轮询 CPU、响应体积、冲突重算、下令到位移时延 | CPU 增加 30%；体积增加 15%；时延翻倍 |

第一次运行找到的卡住原因（确定性复现，待第 10 节第 1 步修复）：

1. **第一段路擦过建筑角**：寻路网格按小半径判断能走，`Siege.walk()` 按单位真实半径检查，路线被丢弃后重试得到同一条路，永远走不出去（例：村民 #22 贴着靶场卡 119 秒；火炮 #1028 卡 69 秒）。
2. **迎面僵持**：两个单位在同一直线上相向而行，碰撞互相推回，`walk()` 的卡住恢复看不到之后被推回，不触发绕行。
3. **围攻被围死的目标**：攻击者原地不动，不转打城墙；每 2 秒同时做全图寻路（每次展开 10608 格），造成约 0.6 秒卡顿；这条路径不经过不可达缓存。

附带发现：每帧约 45 次带 `ctx.filter` 的绘制（`precision-picking.js` 的遮挡剪影描边）在无显卡环境里占大部分渲染时间，需在 iPhone 上用 `?perf=1` 确认；寻路纵向起点 clamp 误用列数（`cols-1`），目前不触发但应顺手修。

渲染和联机数字来自无显卡测试环境与假设的网络延迟，只用于比较版本间变化，不代表真机或线上表现。

## 10. 实施顺序与风险

每一步都在新分支上做，通过全部检查和发布前常规检查后，负责人确认再合并。

1. 先修单位卡住：用发布前检查里的卡住检测找到原因，这是掌控感的地基。
2. 兵种信息面板（第 5 节，可独立先做）。
3. 兵种与建筑精简：用现有的“停用”（`retired`）标记从训练和建造菜单中移除，而不是删除定义，保证旧存档里已有的单位还能加载。
4. 升级线与克制数值：用模拟对战校准，确保高时代的兵在同样的资源和人口下更强（第 2.1 节的表格要反过来）。
5. 电脑对手的打法。
6. 野外据点与地图随机性。
7. 新素材到位后替换贴图。

风险：

- **存档兼容**：旧存档里可能有被删除的单位，用停用标记而不是删除来避免加载失败。
- **电脑 AI**：它的建造和训练清单引用了很多将被删除的单位，需要同步修改。
- **联机**：双方版本必须一致，改完要跑 `check-network.cjs` 和 `check-netcode.cjs`（后者在 `claude/netcode-p0` 分支）。
- **说明与教程**：说明文字、中英文本地化和教程里提到的单位要一起更新。

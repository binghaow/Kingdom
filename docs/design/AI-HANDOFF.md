# 交给其他 AI 实现时的规则与任务模板

适用于 Codex、Claude Code 或任何编码 AI。每次只交一个任务，一个任务对应设计文档里的一节或一步。

## 每次任务都要带上的固定规则

把下面这段原样放在任务开头：

```
你在 GitHub 仓库 binghaow/Kingdom 上工作（游戏《边境王国》）。
开始前必须完整阅读：
1. AGENTS.md（工程、界面审查、素材授权、App Store 合规、性能要求，全部必须遵守）
2. docs/design/roster-redesign.md（权威设计文档；本任务的需求以它为准）
3. 与本任务相关的 docs/ 文件和现有代码
规则：
- 只做本任务指定的那一节，不顺手改别的系统；需要改范围外的东西，先停下来说明并等我确认。
- 在新分支上做，分支名 feature/<简短英文名>；不要直接改 main，不要部署。
- 增量修改现有代码，不重写；保持存档兼容和联机协议兼容，除非设计文档明确要求。
- 不改任何伤害、数值、资源、平衡，除非本任务就是改数值。
- 不新增或替换素材，除非本任务提供了素材文件；缺素材就记录缺口，不要临时画几何图形顶替。
- 完成后必须运行并全部通过：node check-all.cjs、npm run build、node check-artifact.cjs，以及 npm run release-check（若该脚本已存在）。
- 界面改动要按 frontier-ui-audit 在手机竖屏、手机横屏、iPad 横屏、桌面，中英文、操作栏展开/收起下检查，并在 docs/ 写明实际验证证据。
- 设计文档里有勾选框的验收标准，逐条给出是否满足和证据。
- 交付时报告：分支名、提交列表、改了哪些文件、每条验收标准的结果、检查命令输出、仍需真机验证的项。不要说“已上线”。
- 设计文档和代码现状冲突、或设计不清楚时，停下来提问，不要自己猜。
```

## 任务模板

```
[固定规则，见上]

本次任务：实现 docs/design/roster-redesign.md 第 <N> 节「<标题>」。
范围：<一句话列出要做的事>
不在范围内：<列出这次不要碰的东西>
验收：以该节的验收清单为准，另外 <补充的具体要求，可选>。
```

## 推荐的任务顺序（与设计文档第 10 节一致）

1. 「修单位卡住」：用 release-check 的卡住检测定位原因并修复，附修复前后数据。
2. 「兵种信息面板」：第 5 节，可以独立先做。
3. 「兵种与建筑精简」：第 3、4、6 节，用 retired 标记，同步修改电脑 AI 的建造与训练清单、本地化和教程。
4. 「升级线与克制数值」：第 2.1、3.1 节，用模拟对战校准，交付前后性价比表格。
5. 「电脑对手打法」：第 7.1 节。
6. 「野外据点与地图随机性」：第 7.2、7.3 节，先和负责人确认联机确定性方案。
7. 「替换新素材」：按 docs/design/art-audit.md，素材到位后逐批替换并通过素材检查。

## 怎么检查 AI 交回来的结果

- 看它有没有逐条回答验收标准，有没有附上检查命令的输出。
- 看分支的改动文件列表，确认没有改到范围外的系统。
- 让 Claude（或另一个 AI）做一次独立审查：只给它分支名和设计文档对应一节，让它检查实现是否符合设计、有没有回退。
- 自己在手机和电脑上实际玩一局，确认后再合并到 main 并部署。

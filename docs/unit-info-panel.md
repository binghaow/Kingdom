# 兵种信息面板（roster-redesign.md 第 5 节）· 实现与界面审查记录

日期：2026-11-11 · 分支 `feature/unit-info-panel`（基于 `claude/release-gates`）· 审查执行者：Claude（编码 agent），Playwright Chromium 无头浏览器。**不是真机测试。**

## 做了什么

- **单一数据源**：`public/empires.js` 里的克制规则抽成纯函数 `counterMultiplier(攻击者, 目标)`、`structureMultiplier(攻击者)`（打建筑）、`structureFollowup(攻击者)`（榴弹炮 ×1.8、投石机 ×2.5，在后续 `damage()` 链上生效），由 `KingdomSim` 导出。`strike()` 改为调用它们，数值未改（仍是 ×1.65 等）。界面（`public/unit-intel.js`）只调用这些函数和 `sim.stat()`，不写倍率。
- `public/dynasties.js`：榴弹炮打建筑的系数改读共享表；新增只读 `attackInterval()`（奥斯曼学说的 ×0.9 抽成 `volleyDrill()`，`strike()` 行为不变），供界面算每秒伤害。
- **底部选中面板**（`unit-intel.js` + `campaign-ui.js` + `campaign.css`）：攻击（含科技/国家/老兵/难度，差值用绿色或红色小字，如「17 (−13)」是电脑难度系数）、每秒伤害、护甲数值 + 按 role 推导的类别（步兵甲/骑兵甲/器械/舰体/飞行器/建筑…，未新增护甲数值）、射程与速度的「近/中/远」「慢/中/快」小标签 + 数字、克制行「⚔ 克 [图标] ×倍率」「⚠ 怕 [图标] ×倍率」；选中敌方单位时「怕」改为「对付它」。生命沿用面板原有「当前 / 上限」。手机上克制行只显示图标与倍率（名称在 title）。
- **多选**：按兵种显示数量与总生命，点击某类切到该类单体面板（只切换显示，不改变选择，避免影响命令），「‹ 全部」返回；战斗中只原地更新生命文字，按钮不会在手指下被替换。
- **ⓘ 弹窗**（在原「兵种与建筑档案」上扩展）：最上方一句话定位（克/怕标签）、与同建筑兵种对比的条形图（生命、每秒伤害、护甲、射程、速度、人口）、「克制 / 被克制」两列（每个兵种图标与精确倍率，含打建筑倍率）、升级潜力、对它生效的科技（已研究打勾，半研究 ◐）。旧的手写「克制加成」段（例如蒸汽装甲车「建筑 ×1.35」）对兵种不再显示，改由函数结果给出。
- **升级线**：升级研究机制尚未实现。按设计「等升级机制做好后再开启」：数据驱动预留（`LINES`：长枪线、远程线），**底部面板的「长枪线 1/3」默认关闭**（`UPGRADES_ENABLED=false`）；ⓘ 弹窗显示同一条线上现有的独立兵种作参考（每阶实际数值、所需时代、训练建筑，当前阶高亮，研究费用显示「—」并注明待升级机制）。理由：参考信息有用且不虚构；底部「1/3」会让玩家以为能研究升级，所以先关。
- **科技列表**不手写规则：对每个科技构造一个只读视图（`Object.create(sim)` 只遮蔽 `s.tech`），比较 0 级与满级下 `stat()` / `attackInterval()` 的差，有差即列出。
- 中英文：新文字在 `public/locale-campaign.js` 的 `KingdomUnitIntelText`（不放进共享子串字典，避免「近」「中」等短词改写其它文本）；兵种/建筑/科技名走现有字典。面板按当前语言渲染，切换语言即重绘。
- 手机布局：面板是停靠在底栏上方的一条（底栏折叠时 iPad 也一样）；小地图、地图工具栏、触控工具条按面板实测高度 `--ui-h` 上移，不被覆盖。桌面 / iPad 展开底栏时面板在选中栏内（选中栏加宽到 300–340px，命令区照旧横向滚动；单位的状态描述行在此状态隐藏，完整描述在 ⓘ）。

`check-unit-intel.cjs` 在 VM 里运行真实的 `unit-intel.js` 渲染代码：

1. ⓘ 两列列出的兵种集合与倍率 == 对全部可训练单位调用 `counterMultiplier` 的结果（不多不少）；打建筑倍率 == `structureMultiplier × structureFollowup`。
2. 底部面板每个克制图标的倍率（或范围）== 函数结果的 min/max。
3. 10 国 × 全部近战/远程攻击者 × 全部可训练单位与 2 种建筑，真实 `strike()` 掉血 == `max(1, stat(攻击) × 界面倍率 − 目标护甲)`；冷却 == `attackInterval()`。投石机 ×2.5 仍是 `siege.js` 里的字面量（为避免和并行的卡住修复分支冲突没有改该文件），由这一项实测保证不会和共享表不一致。
4. profile、科技探测、弹窗渲染前后 `sim.serialize()` 字节相同（不写模拟状态）。
5. 英文渲染无中文残留；中文正常。
6. 升级线数据引用的兵种都存在，底部默认不显示。

## 发现（未修改，交负责人决定）

1. 蒸汽装甲车定义里有 `bonus:{building:1.35}`，但建筑没有 `role`，这个加成在伤害里从未生效；旧 ⓘ 弹窗却显示「建筑 ×1.35」。现在界面显示真实结算（无此加成）。是否让它生效属于数值调整。
2. 棱堡炮塔是建筑但 `role:'cannon'`，骑兵打它按 ×1.65 结算（面板的克制列表只列可训练单位，没有列出它）。
3. 底栏展开/收起按钮 `#sheet-toggle`（top:−17px）被 `.selection{overflow:hidden}` 裁切：在基线提交上同样复现（中心点命中 footer，上沿命中战场画布），触屏上可能很难点中。与本任务无关，未修改。
4. 敌方单位攻击显示「17 (−13)」：这是电脑难度的伤害系数（`profile(team).damage`），与战场结算一致。

# P5 千兵规模 · 第一段进度

分支 `feature/p5-scale`（基于 main d1dfb30），2026-11-25。对应 `docs/architecture/redesign-plan.md` P5。测量基线与前 10 热点见 `docs/p5/profile-baseline.md`。
原则：测量驱动、收益最大的先做；**能做到“答案逐个相同”的就不改玩法**。除流场外，本段所有改动的录像校验值、规模基准校验值、8 方 17 分钟对局校验值都与 main 相同。

## 1. 做了什么

| 项 | 改动 | 玩法影响 |
|---|---|---|
| 空间服务 `src/core/spatial.js` → `public/kingdom-spatial.js` | 1) 32 px “肯定空旷”地形掩码：`blocked()` 在掩码为 1 的格子里跳过地形精确计算；2) BoxIndex：建筑（按 v44 的每种建筑可达半径）和城墙矩形进 192 px 网格；3) PointGrid：计数排序的单位网格；4) UnitColumns：x/y/半径/队伍/存活的 TypedArray 列 + id→行号表 | 无（答案相同） |
| 碰撞 `separateCrowd` | 同样的 128 px 分桶窗口、同样的 (i, j) 顺序与推开量，改在列上算（推开时同时写回对象），平方距离先筛 | 无 |
| 自动索敌 `autoTargetNear` | 同一 256 px 窗口、同一名单顺序，Map 分桶换成 PointGrid + 列 | 无 |
| 防御塔索敌（sysBuildings） | 单位网格只取射程范围内，再按原条件、原顺序挑最近 | 无 |
| 城墙 | `blocked()` 与穿墙检测只看附近的墙矩形 | 无 |
| 迷雾视线 `sightBlocked` | 每个观察者只测 ±800 px 内的悬崖（备忘） | 无 |
| 清理 | 没有单位/建筑/资源消失时不替换数组（id 索引、空间索引在平静的步里保持有效） | 无 |
| **同目标共用流场**（engine `flowPath` / `FlowField`） | 同一网格 4 s 内第 6 次请求同一终点格 → 从终点开 Dijkstra 流场，按需生长（每步 ≤ 6000 格），之后的请求顺着流场取路线；最多 8 张、12 s 不用丢弃、网格变了全丢；起点被占/跨区域/没长到时照旧 A* | 路线仍是最短路，只在等长岔路上可能换一条 → **录像重录**（见第 3 节） |
| 电脑思考 | AI 阶段内状态不会变（P4 4a 检查），`view(team)` 每个阶段只算一次，给调用者新数组 | 无 |
| 修复（main 上也有） | 海岛图电脑运输船：港口被丢掉后进入返航阶段时读 `F.port.x` 崩溃（straits 专家对专家种子 5，**真实对局会让模拟停住**），一行守卫 | 只影响原来崩溃的情况 |

数据布局（第 4 项）的范围按评估缩小：只把“扫描全军”的三个循环（碰撞、索敌、防御塔）放到列上；没给单位对象加 getter 外观（单位是纯 JSON，存档/快照/结构化克隆/校验值都依赖自有数据属性；而单位循环的开销主要在 4 层 walk、12 层 stat 的方法链）。理由见 `decisions.md`。
